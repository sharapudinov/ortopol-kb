# ortopol-kb — установщик базы знаний по корпусу И. И. Шарапудинова

Код, который **строит, ищет и разворачивает** базу знаний проекта ortopol: корпус работ
И. И. Шарапудинова (68 источников, ~2500 страниц) в Postgres 17 + pgvector с двумя
ключами поиска — полнотекстовым (`russian`-стемминг) и семантическим (bge-m3, 1024).

**Здесь только код.** Данные живут в data-артефакте, из которого база и
разворачивается (ниже); граница «код — в git, данные — в артефакте» закреплена
тестом (`tests/test_build_corpus.py::test_index_is_outside_git`).

Артефакт — продукт сборки из живой базы (источник истины — база плюс этот код) и
распространяется **релиз-ассетом при репозитории**, а не файлом в git — сознательно:
релиз-ассет заменяем, поэтому правка правового режима одного документа — это UPDATE
в базе, пересборка и замена ассета, тогда как закоммиченный блоб остался бы в
git-истории каждого клона навсегда; вдобавок каждый пересобранный снимок (десятки
МиБ на каждое обновление корпуса) ложился бы в историю целиком.

## Что где

| | |
| --- | --- |
| `pg_schema.sql` | схема: `corpus.documents` / `corpus.pages` / `corpus.embedding_model` |
| `build_corpus.py`, `pdf_extract.py`, `encoding.py`, `report.py` | извлечение текста из PDF, классификация качества извлечения, отчёт о покрытии |
| `pg_load*.py`, `pg_source_urls.py`, `pg_embed.py` | загрузчики (обычный, транскрипция, djvu, метаданные, блобы источников) и эмбеддинги |
| `pg_search.py` | поиск: `--mode fulltext\|vector\|hybrid` |
| `corpus_completeness.py` | предикат полноты: перечисляет каждый файл под `theory/`, падает на неклассифицированном, сверяет страницы с `pdfinfo` |
| `deploy/` | сборка артефакта, docker-compose стек, смок-тест, статические проверки состава |
| `EXTENDING.md` | процедуры расширения базы (новая работа, внешний источник, нечитаемый источник, результаты экспериментов) |
| `deploy/AGENT_GUIDE.md` | гайд для **получателя** артефакта: как развернуть и как этой базой пользоваться |

Плоская раскладка без пакетов: каждый скрипт запускается как `python3 <скрипт>.py`,
тесты — `python3 -m unittest discover -s tests -t tests` из корня репозитория
(286 тестов, без Docker и без сети; часть требует живой базы и корректно
пропускается/падает с внятным сообщением, если её нет).

## Развёртывание из артефакта

Артефакт самодостаточен — получателю этот репозиторий не нужен:

```bash
tar --zstd -xf kb-<профиль>-<дата>.tar.zst -C kb-current
cd kb-current
cp .pgenv.example .pgenv        # заполнить PGPASSWORD
docker compose --env-file .pgenv -p kb up -d
python3 profile_checks.py       # состав = манифест (статически, без Docker)
python3 smoke_test.py           # полная самопроверка развёртывания
```

Подробности, три режима поиска, семантика доверия к страницам и границы профиля —
в `deploy/AGENT_GUIDE.md`, который лежит внутри артефакта.

## Сборка артефакта: два профиля

```bash
set -a; . ../corpus/.pgenv; set +a
python3 deploy/build_package.py --profile full     # по умолчанию
python3 deploy/build_package.py --profile public
```

Результат — `../corpus/deploy/kb-<профиль>-<дата>.tar.zst` (вне git по построению).

**`full`** — служебный профиль владельца корпуса: вся база, обе схемы (`corpus` и
`measurements`), для переноса между своими машинами.

**`public`** — распространяемый профиль: схема `corpus`, состав каждого документа
следует его правовому режиму:

| `public_distribution` | что уезжает |
| --- | --- |
| `full-text` | всё: `body`, `tsv`, `embedding`, `source_blob` |
| `internal` | всё (наши собственные служебные документы, INDEX/THEMES) |
| `metadata-only` | библиография, правовые колонки (`legal_class`/`legal_note`), `source_sha256` для сверки со своим экземпляром, ссылка на оригинал; у страниц — `page_number` + `embedding`, семантический поиск по ним работает |

Классификация — **данные, а не код**: колонки `legal_class`, `public_distribution`,
`legal_note` в `corpus.documents`, заполняет владелец по правовому досье. Сборщик их
только читает (`deploy/legal_profile.py`), никаких списков id и шаблонов имён в коде
нет — это проверяется тестом. Документ без классификации или с незнакомым значением
**роняет сборку**: догадка здесь недопустима ни в одну сторону.

## Состав и его проверка

- В `public` полным текстом едут работы, чей правовой режим это позволяет (книги с
  © автора, CC-BY, издания с © авторов, произведения советского периода); остальные
  представлены библиографией, метаданными, векторами и ссылкой на оригинал — текст у
  таких документов пуст по праву, а не по ошибке извлечения.
- Состав артефакта проверяется по его собственным байтам:
  `python3 deploy/profile_checks.py --artifact-dir <распакованный>` — схемы = манифест,
  классификация полна, у `metadata-only` нет ни блоба, ни текста, у остальных есть и
  то и другое, у каждой страницы есть вектор. Exit 0 — состав соответствует профилю.

## Два корня

`paths.py` различает `kb_root()` (этот чекаут: только код) и `data_root()` (дерево
данных владельца корпуса; получателю артефакта не нужно ни то, ни другое —
артефакт самодостаточен).
