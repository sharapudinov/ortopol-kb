# Расширение базы знаний: внешние источники и результаты экспериментов

Процедурный гайд для того, кто пополняет базу. Гайд для *потребителя* базы —
`deploy/AGENT_GUIDE.md`; здесь — как класть знание внутрь, не ломая
инварианты, на которых база держится.

## Принципы, которые не обсуждаются

1. **Полнота — предикат.** `corpus_completeness.py` перечисляет каждый файл под
   `theory/` и падает на неклассифицированном. Падение с `UNCLASSIFIED` — не ошибка,
   а **точка входа этой процедуры**: новый файл обязан быть либо включён, либо исключён
   с причиной, решение принимается здесь и записывается в `classify()`.
2. **Запись без семантического ключа не существует для поиска.** Всё, что положено в
   базу, проходит `pg_embed.py`; его финальная строка «все записи-результаты несут
   семантический ключ» — часть любой операции расширения.
3. **Внешний факт — это «источник X утверждает Y», никогда «Y».** Пара
   `source_tier` (откуда) + `our_stance` (что мы с этим делаем) обязательна;
   `relied-upon` ставится только после сверки человеком с самим источником.
4. **Отрицательный результат записывается в первую очередь** — он не оставляет
   ни кода, ни теста, и без записи будет переоткрыт за те же деньги.
5. **Копирайт.** Полные тексты чужих изданий (PDF, djvu, извлечённый/транскрибированный
   текст, дампы базы) живут **вне git** — в `theory/` и `corpus/`. В этом репозитории
   только код и процедуры. Это правило не имеет исключений, потому что репозиторий
   предназначен к публикации.
6. **Правовой режим документа — данные, а не знание в голове.** Каждая строка
   `corpus.documents` несёт `legal_class`, `public_distribution`, `legal_note`
   (основание одной строкой). Ни одного NULL: `deploy/build_package.py --profile public`
   ОТКАЗЫВАЕТСЯ собирать артефакт, если у документа нет классификации или значение
   `public_distribution` ему неизвестно — неклассифицированный документ роняет сборку,
   а не уезжает наружу «по умолчанию». Установленный режим «в публичный артефакт не
   входит вовсе» — это значение `excluded`, тоже данные: решение владельца записывается
   в базу, а не в список исключений внутри сборщика.

## Карта хранилища

| Что | Где | Ключевые поля |
| --- | --- | --- |
| Документы-источники | `corpus.documents` | `extraction_state`, `source_dir`, `source_tier`, `source_path` (generated из `source_dir` + `filename`), `source_url`, `note`, `legal_class`, `public_distribution`, `legal_note` |
| Страницы | `corpus.pages` | `body`, `tsv` (generated, russian), `embedding` (bge-m3/1024) |
| Модель эмбеддингов | `corpus.embedding_model` | одна строка; запрос эмбеддится ТОЙ ЖЕ моделью |
| Прогоны исследований | `measurements.run` | `question`, `arbiter`, `reproduce`, `verify_query`, `rules_out`, `verdict`, фасеты `family`/`area`/`varied`, `embedding` |
| Поточечные данные | `measurements.<эксперимент>` | своя таблица на эксперимент, FK на `run` |

`extraction_state` — ярус доверия странице:

- `clean` / `recoded` — механическое извлечение: точно, но выносные формулы сплющены;
- `degraded` — читаемо, известные потери (лигатуры), масштаб в `note`;
- `transcribed` — прочитано моделью с отрисовки: формулы в LaTeX, перед цитированием
  в код сверять с изображением;
- `ocr` — чужой слой распознавания: ошибки есть и не квантифицированы;
- `metadata` — курируемые нами описания (INDEX/THEMES);
- `unreadable` — строка-заглушка, чтобы отчёт о покрытии не врал.

## Процедура A: добавить работу ИИШ (в существующий корпус)

1. Положить PDF в `theory/iis/` (плоско — `source_path` generated из этой конвенции).
2. Дописать строку в `INDEX.md`: год, файл, название, mathnet-ссылка (если есть).
3. `python3 build_corpus.py && python3 pg_load.py` — извлечение классифицирует
   состояние само; `pg_load` не тронет документы чужих конвейеров
   (transcribed/ocr/metadata — защищено предикатами и тестом).
4. Если состояние `broken` — конвейер транскрипции (Процедура C).
5. `python3 pg_source_urls.py && python3 pg_load_blobs.py && python3 pg_embed.py`
   — блоб исходника обязателен: база самодостаточна, целостность держится хешем.
6. **Правовой режим** новой строки: `legal_class` + `public_distribution`
   (`full-text` | `metadata-only` | `internal` | `excluded`) + `legal_note` с
   основанием. Решение принимает владелец, не агент; источник фактов —
   `corpus/legal-regimes-dossier.md`. Досье не покрывает издание — это не `metadata-only`
   «на всякий случай», а `excluded` до прояснения. Без классификации `--profile public`
   не соберётся (принцип 6 выше).
7. **Закрытие:** `python3 corpus_completeness.py` → exit 0 и полный прогон тестов.

## Процедура B: добавить ВНЕШНИЙ источник (не ИИШ)

Внешние источники — чужие статьи, препринты, справочники — живут в
`theory/external/` (плоско, как `iis/`) и имеют собственный конвейер:
`pg_load_external.py`, реестр `EXTERNAL_INDEX.md`, класс
`external-literature`. Класс всегда `public_distribution = 'excluded'`:
**ни байта чужой работы не уходит в public-артефакт** — ни текста, ни блоба,
ни строки документа, ни вектора страницы.

Хранить можно два вида записи, и разница между ними — правовая:

- **PDF** — когда тело доступно и лицензия названа (препринт arXiv, ОА-копия
  автора). Загружается постранично, ищется обоими ключами.
- **`.md`-справка** — когда тела у нас НЕТ (пейвол, издание не оцифровано).
  Наш собственный текст: выходные данные, реферат с указанием источника,
  зачем работа нужна и **что по ней не проверено**. Честная форма записи
  «работа существует, вот адрес, мы её не читали».

Шаги:

1. Положить файл в `theory/external/`. Расширения только `.pdf` и `.md`.
2. Дописать строку в `theory/external/EXTERNAL_INDEX.md`. Ровно шесть колонок,
   `|` внутри ячейки запрещён:
   `файл | source_tier | канонический URL | правовой режим | библиография | зачем взяли`.
   Колонка «зачем взяли» обязательна: источник без ответа «зачем» в базу не
   кладётся, база — не закладки. Колонка «правовой режим» называет **основание**
   (какая лицензия, где и когда проверена) и уходит в `legal_note`; решение
   «уезжает или нет» она НЕ принимает — оно у класса одно и то же.
   `source_tier` — откуда взято по факту: `arxiv-oa`, `publisher-paywalled`, …
   (не `local_corpus`, это тир самого корпуса ИИШ).
3. `python3 pg_load_external.py` — извлекает PDF, читает `.md`, ставит
   `source_dir = theory/external`, `legal_class`, `public_distribution`,
   `source_url`, `note` (библиография + зачем). Реестр индексируется тоже —
   как наш собственный документ (`internal-metadata` / `internal`, наравне с
   `INDEX.md`).
4. `python3 pg_load_blobs.py && python3 pg_embed.py pages`.
5. **Закрытие то же:** `corpus_completeness.py` exit 0 + полный прогон тестов.
   Предикат полноты проверяет обе стороны реестра (файл без строки, строка без
   файла), совпадение URL с базой и то, что каждая строка под
   `theory/external/` несёт положенный ей режим.

Почему конвейер отдельный, а не флаг у `pg_load.py`: у документов разный
правовой режим, разный тир, и `.md`-справки в манифесте извлекателя не
появляются вовсе. Оба загрузчика ограничивают свои удаления собственным
`source_dir`, поэтому ни один не может снести документы другого — внешние PDF
несут обычное состояние `clean`, и список «чужих состояний» их бы не защитил.

Кандидаты следующей очереди записаны в issue #12: классические справочники
(НСУ, схема Аски, DLMF), литература по минимальным/доминантным решениям
рекуррентностей, работы по моментам изображений и Wellman/Lucidity.

## Процедура C: нечитаемый источник

Проверено и записано (issue #12): криптоанализ подстановки глифов НЕ работает —
рендерить и читать.

1. `pdftoppm -r 150 -png` (или `ddjvu -format=tiff -scale=150` + `magick`) в scratch.
2. Транскрипция партиями ~30 страниц, правила жёсткие: дословно; формулы в LaTeX;
   **сомнение = `[?]`, никогда не правдоподобная подстановка**; артефакты набора самой
   книги — пометкой, не молчаливым исправлением. Проверять выборочно: подмена печатного
   кросс-референса «логичным» уже случалась и была откатана по изображению.
3. `pg_load_transcribed.py --text-dir <dir>` (state `transcribed`);
   для djvu с готовым OCR-слоем — `pg_load_djvu.py` (state `ocr`) как временный ярус,
   транскрипция поверх — когда качество важно (для центральных документов — сразу).
4. Закрытие как в A.

## Процедура D: результаты экспериментов

Полностью живой путь, менять код не нужно.

1. **До замера — искать**: `pg_search.py` (hybrid) + фасетный запрос по
   `measurements.run` (`family && array[...] and area && array[...]`). Пустой результат
   записывается в спайке явно.
2. Поточечные числа — в свою таблицу `measurements.<имя>` (FK на run). Сырьё в
   scratch/`​/tmp` не считается сохранённым.
3. Строка в `measurements.run`: `question`, `arbiter`, `reproduce` (одна команда
   пересоздать), `verify_query` (вывод переспрашивается против ИМЕЮЩИХСЯ данных —
   «находка есть цитата запроса»), `rules_out` (что исключает — для отрицательного
   результата это вся ценность), фасеты, `verdict`. Вердикт пишет оркестратор,
   не агент-исполнитель.
4. `python3 pg_embed.py runs` — семантический ключ.
5. Решение, которое следует из прогона, — комментарием к issue: трекер источник
   истины, база производна.

## Процедура E: новый ВИД записи

Новый вид результата (напр. записи-находки из issue #14, профили прогонов из #15):

1. Схема: своя таблица в подходящей схеме (`corpus` — про источники,
   `measurements` — про наши данные), с `embedding vector(1024)` если запись должна
   находиться по смыслу.
2. Строка в `TARGETS` в `pg_embed.py` (таблица, выражение текста, предикат
   «есть содержание») — это и есть регистрация вида записи; отдельный скрипт — ошибка.
3. Тест на инвариант ключа и на выживание при перезагрузках (по образцу
   `test_ordinary_reload_preserves_aux_documents` — этот класс дефекта ловили дважды).
4. Если вид записи привязан к файлам на диске — правило в `classify()`.

## Чек-лист закрытия ЛЮБОЙ операции расширения

Из корня ЭТОГО репозитория (`.pgenv` живёт в дереве данных, рядом с `theory/`):

```bash
set -a; . ../corpus/.pgenv; set +a
python3 pg_load_blobs.py        # исходники в базе, хеши сходятся
python3 pg_embed.py             # ... несут семантический ключ
python3 corpus_completeness.py  # exit 0
python3 -m unittest discover -s tests -t tests  # OK
```

`pg_embed.py` без аргументов обсчитывает и `measurements.run`; когда правка
касается только корпуса, а прогоны пишет кто-то другой, цель называется явно:
`python3 pg_embed.py pages`.

Пока четыре команды не зелёные — операция не завершена и «база пополнена» не утверждается.

## Анти-паттерны (каждый оплачен в этом проекте)

- Сырые числа в scratch как «сохранённые» — теряются при первой чистке.
- «Отсутствует в индексе» = «отсутствует в корпусе» — неверно при покрытии < 100%.
- Truncate-загрузчик «для простоты» — дважды молча уничтожал дорогие артефакты
  (векторы; транскрипцию).
- Эмбеддинг запроса другой моделью — дистанция считается, результат мусор, ошибки нет.
- Молчаливое «исправление» источника при транскрипции — подмена проверяемого
  непроверяемым.
- Требование к данным, которого источник не может выполнить (URL у монографии без
  URL), — ложные падения приучают игнорировать предикат.
